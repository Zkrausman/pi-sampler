# Implementation Plan: AIDEV-132

## 1. Effort & Risk
**Effort**: High (3-4 weeks for all slices). Due to complexity, slices will be implemented via stacked pull requests or child tickets.
**Risk**: High. This ticket establishes critical security and integrity boundaries for evaluation. Ensuring evaluation context is entirely isolated from active sessions, enforcing strict citation grounds without hallucination, and scanning for sensitivity data leaks involves high security risk. The design must prevent OOM crashes via strict bounds, block symlink traversal, avoid cyclic dependencies, and never expose live credentials to the evaluator process.

## 3. Step-by-Step Execution

**Slice 1: Immutable retrospective evaluation packets and citation enforcement**
1.  Define TypeBox schemas for `retrospective-packet-v1` and `retrospective-v1`.
2.  Implement exporter scripts `scripts/export-retrospective-packet-v1-schema.mjs` and `scripts/export-retrospective-v1-schema.mjs`.
3.  Develop `src/retrospectives/packet-builder.mjs` to map Episode bounds deterministically to an immutable retrospective packet payload. **Crucially, enforce strict byte-size limits and utilize streaming where possible to prevent OOM vulnerabilities. The builder must fail-closed if the payload exceeds memory bounds.**
4.  Implement `src/retrospectives/citation-enforcer.mjs` to validate all evidence citations strictly against the snapshot. **It must explicitly fail-closed (rejecting the entire retrospective) on timeout, malformed snapshot parsing, or execution failures.**
5.  Implement tests mapping to `tests/retrospective-packet-v1.test.mjs` and `tests/retrospective-citation-enforcer.test.mjs`.

**Slice 2: Isolated, versioned evaluator execution with uncertainty and counterevidence**
1.  Implement `src/retrospectives/evaluator-runner.mjs` enforcing a clean environment unlinked from active/unrelated conversational context.
2.  **Add strict boundary sanitation to explicitly prohibit path traversal and symlink escapes when the evaluator reads the snapshot or writes counterevidence.**
3.  Wire evaluator input entirely to the snapshot hash generated by `packet-builder.mjs`.
4.  Ensure prompt construction strictly requires and schema validation strictly enforces the population of `uncertainty`, `counterevidence`, and alternative causal models in the retrospective report.
5.  Implement `tests/retrospective-evaluator-isolation.test.mjs`.

**Slice 3: Sensitivity scanning plus versioned human approve/edit/reject decisions**
1.  Define `retrospective-review-v1.mjs` schema specifying review states (`approved`, `edited`, `rejected`, `deferred`).
2.  Develop `src/retrospectives/sensitivity-scanner.mjs` to block outputs containing sensitive information. **Do NOT load live credentials (e.g., `.pi/credentials`) into memory to use as a blocklist.** Rely entirely on regex/entropy-based pattern matching or external sanitized dictionaries to prevent unprotected state leakage.
3.  Develop `ledgers/retrospective-ledger.mjs` for persistence. **Strictly enforce a unidirectional, acyclic dependency graph** (e.g., using an event bus or ensuring the retrospective ledger is purely downstream) to prevent import cycles or infinite loops with `EpisodeEvolutionLedger`.
4.  Update governance path policies and generate `docs/specs/RETROSPECTIVE-V1.md`.
5.  Implement tests mapping to `tests/retrospective-sensitivity-scanner.test.mjs` and `tests/retrospective-review-decision.test.mjs`.

## 4. Test Matrix
| Category | Test Case | Expected Result |
| :--- | :--- | :--- |
| Content Integrity | Packet payload size exceeds byte limits | `packet-builder` fails closed, throws `PayloadSizeLimitError` to prevent OOM |
| Citation Strictness | `citation-enforcer` times out or crashes during validation | Fails closed, rejects evaluation immediately |
| Context Isolation | Evaluator attempts to read active session environment variable/context | Throws `ExecutionIsolationError` |
| Symlink Escapes | Evaluator attempts to navigate outside sandbox via symlinked paths | Throws `PathTraversalViolationError` and aborts |
| Sensitivity Policy | Evaluation output contains high-entropy credential (generated dynamically at runtime in memory) | `sensitivity-scanner` blocks and drops payload |
| Governance/Review | Submitting review transition (`approved`) with stale `expectedRevision` | Throws `OptimisticConcurrencyError` |
| Cyclic Dependency | Retrospective ledger initialization | Successfully initializes without triggering `EpisodeEvolutionLedger` circular loop |
| Analytical Quality | Report payload omits `counterevidence` section | Validation schema rejection at runtime |
