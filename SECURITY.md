# Security policy

## Supported code

The current `main` branch's active local tooling is the supported code line for
security reports. Retired self-evolution extension versions receive no active
compatibility or maintenance commitment; report a vulnerability in historical
code with its affected commit or published version so it can be assessed.

## Reporting a vulnerability

Do **not** open a public issue for a suspected vulnerability or include a
credential, access token, session archive, or customer data in a report.

Use [GitHub private vulnerability reporting](https://github.com/Zkrausman/pi-sampler/security/advisories/new)
for this repository. Include a minimal reproduction, the affected version or
commit, impact, and any mitigation you have identified.

Use the private reporting channel so the report is not exposed in a public issue
or pull request. Include only the information needed to reproduce and assess the
issue; do not include credentials, access tokens, session archives, or customer
data.
